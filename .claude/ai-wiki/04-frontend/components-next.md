# components-next (current UI system)

## Purpose

`app/javascript/dashboard/components-next` is the current-generation Vue 3 component tree for the agent dashboard. It is aliased as `next/` in `vite.shared.ts` (`next: path.resolve('./app/javascript/dashboard/components-next')`), so imports appear either as `next/...` or `dashboard/components-next/...` depending on the file.

It is not just a UI-primitives kit. Per `CLAUDE.md` ("Use `components-next/` for message bubbles (the rest is being deprecated)"), this directory is where new/rewritten features land wholesale — both the low-level design-system primitives (`button/`, `dialog/`, `dropdown-menu/`, `combobox/`, `table/`, `checkbox/`, `switch/`, `input/`, `avatar/`, `filter/`, `pagination/`, etc.) and full feature/page implementations (Contacts, Companies, HelpCenter, Campaigns, Captain, AssignmentPolicy, NewConversation compose flow, WhatsApp template preview). The legacy `dashboard/components/` tree is being migrated into this one incrementally; some legacy components (e.g. `ConversationItem.vue`) already import cards/bubbles from here.

Scale (sampled via `find`/`wc`): 538 files total, ~234 `.vue` components, 89 Histoire `.story.vue` files (`histoire.config.ts`, `pnpm story:dev`), and 20 `.spec.js` unit-test files. Given the size, this page covers the structure and the central subsystems (message rendering, filters, sidebar, new-conversation compose) rather than every component.

## Key Files & Classes

Message rendering (the part CLAUDE.md calls out as the active system):
- `app/javascript/dashboard/components-next/message/Message.vue` — the per-message component. Computes `variant` (user/agent/activity/private/bot/error/template/email/unsupported), `orientation` (left/right/center), which bubble component to render (`componentToRender`), avatar info, and context-menu enabled options; provides `MessageContext` via `provideMessageContext`.
- `app/javascript/dashboard/components-next/message/MessageList.vue` — renders a list of messages, computes `groupWithNext` (same sender + same message type + same minute), resolves `inReplyTo` (checks current list, then Vuex `getSelectedChat`, then fetches via `MessageApi.getPreviousMessages` and caches in a local `Map`).
- `app/javascript/dashboard/components-next/message/provider.js` — `provideMessageContext`/`useMessageContext` (Vue `inject`/`provide` pair); throws if a bubble is used outside a `<Message>` ancestor. Also exposes `filteredCurrentChatAttachments` from the `getSelectedChatAttachments` Vuex getter.
- `app/javascript/dashboard/components-next/message/constants.js` — `MESSAGE_TYPES`, `MESSAGE_VARIANTS`, `SENDER_TYPES`, `ORIENTATION`, `MESSAGE_STATUS`, `ATTACHMENT_TYPES`, `CONTENT_TYPES`, `VOICE_CALL_STATUS`/`VOICE_CALL_DIRECTION`/`VOICE_CALL_END_REASON` — the shared vocabulary every bubble and the list consume.
- `app/javascript/dashboard/components-next/message/bubbles/` — one component per rendering variant: `Text/Index.vue`, `Image.vue`, `File.vue`, `Audio.vue`, `Video.vue`, `Embed.vue`, `Location.vue`, `Contact.vue`, `Form.vue`, `CSAT.vue`, `VoiceCall.vue`, `Email/Index.vue`, `InstagramStory.vue`, `Dyte.vue`, `WhatsappFlowResponse.vue`, `Text/WhatsappReferral.vue`, `Fallback.vue`, `Unsupported.vue`, `Activity.vue`, plus `Base.vue`/`BaseAttachment.vue` shared wrappers that apply the variant background/rounding classes and read from `useMessageContext()`.
- `app/javascript/dashboard/components-next/message/helpers/whatsappFlowResponse.js` — parses WhatsApp Flow response JSON for the flow-response bubble (has its own spec).

Sidebar / navigation:
- `app/javascript/dashboard/components-next/sidebar/Sidebar.vue` (largest file in the tree, ~1100 lines) — the primary dashboard left-nav: account switcher, channel list, search shortcut, changelog card, "compose new conversation" entry point. Feature-flag/plan-gates things like Calls (`isOnChatwootCloud || isEnterprise`, with a comment noting Calls only runs on the enterprise-only API so it's hidden on Community to avoid a dead-end CTA). Consumed from `app/javascript/dashboard/routes/dashboard/Dashboard.vue`.

## How It Fits Together

- **Consumed by legacy `dashboard/components/`**: `MessagesView.vue` (`app/javascript/dashboard/components/widgets/conversation/MessagesView.vue`) imports `MessageList` as `next/message/MessageList.vue` — this is the live conversation-view message pane. `ConversationItem.vue` imports `ConversationCard` from here for conversation-list rows. This confirms components-next is not an isolated sandbox; it's wired directly into the current production conversation view.
- **Vuex/Pinia store**: pulls conversation/message data via `useMapGetter` (`inboxes/getInbox`, `getSelectedChat`, `getSelectedChatAttachments`, `globalConfig/isOnChatwootCloud`, `globalConfig/isACustomBrandedInstance`) — see [[dashboard-store]].
- **API client layer**: `MessageList.vue` calls `MessageApi.getPreviousMessages` (`dashboard/api/inbox/message.js`) directly to backfill a reply-to message not present locally — see [[api-client]].
- **Backend models it reflects**: message/attachment/sender shapes documented in JSDoc typedefs in `message/Message.vue` and `message/provider.js` mirror the Rails `Message`/`Attachment` serializers — see [[models]] and [[messages-services]].
- **Shared/composables layer**: depends on `shared/helpers/mitt` (event bus), `shared/constants/busEvents` (`BUS_EVENTS.TOGGLE_REPLY_TO_MESSAGE`, `BUS_EVENTS.SCROLL_TO_MESSAGE`), `shared/composables/useBranding` (`replaceInstallationName`, per the branding/white-labeling convention in `CLAUDE.md`), `shared/helpers/MessageFormatter.js` — see [[composables-mixins-helpers]] and [[shared-design-system]].
- **Feature flags / plan gating**: `Sidebar.vue` reads `dashboard/featureFlags` (`FEATURE_FLAGS`) and gates the Calls nav entry on `isOnChatwootCloud || isEnterprise` rather than a hard Enterprise-only check, with an explicit comment explaining why (Calls API is enterprise-only; Cloud always runs Enterprise).
- **WhatsApp specifics**: `message/bubbles/Text/WhatsappReferral.vue` renders click-to-chat ad referral metadata (`contentAttributes.referral`), and `message/bubbles/WhatsappFlowResponse.vue` + `message/helpers/whatsappFlowResponse.js` render WhatsApp Flow submissions — both are UI-side reflections of webhook payload fields documented on the backend; see [[whatsapp]]. `Conversation/ReferralBubble.vue` is the conversation-level counterpart: it renders the CTWA ad-referral object stored on `conversation.additional_attributes.referral` (captured by the backend incoming-message service), surfaced above the message list via `MessagesView.vue`.
- **Captain AI**: `message/CaptainGenerationDetails.vue` and `SENDER_TYPES.CAPTAIN_ASSISTANT` in `message/constants.js` render Captain-generated replies distinctly (own bubble color, "report" context-menu option gated on `isOnChatwootCloud && isCaptainMessage`); see [[captain-ai]].
- **Routes**: most `routes/dashboard/{contacts,companies,campaigns,helpcenter}/pages/*.vue` files are thin wrappers around `components-next/{Contacts,Companies,Campaigns,HelpCenter}/Pages/...` — see [[dashboard-routes-components]].

## Product Behavior

- The message bubble rendering here (`Message.vue`'s `componentToRender` switch) is the concrete implementation behind the official user-guide's message-bubble/conversation-view behavior across channels — e.g. CSAT bubbles (Features explained: CSAT surveys), WhatsApp interactive/flow responses and referral ads (Other channels: WhatsApp; Advanced features: interactive messages, WhatsApp templates), email thread rendering with quoted/reply content (Other channels: Email), and voice-call status bubbles (Voice Channels: Twilio voice / WhatsApp voice calling).
- `NewConversation/ComposeConversation.vue` and its `WhatsAppOptions.vue`/`WhatsappTemplate.vue`/`ContentTemplateForm.vue` implement the compose-new-conversation flow including WhatsApp template selection, matching the Advanced features guide topics on WhatsApp templates and Twilio content templates.
- `filter/ConversationFilter.vue` and `filter/ContactsFilter.vue` implement the "conversation filters" and contact segmentation features described under Advanced features / How To (contact segmentation, filter folders).
- `captain/` components implement the dashboard side of the Captain AI-agent feature guide (assistants, documents, FAQs, scenarios/guardrails, custom tools).

## Notes for AI Agents

- **`next/` alias**: many files here import each other via the `next/...` alias (e.g. `next/icon/ChannelIcon.vue`, `next/icon/provider`) rather than a relative or `dashboard/components-next/...` path. Both resolve to the same directory (`vite.shared.ts`); don't assume `next/` is a separate package.
- **Bubbles must live under a `<Message>`**: `useMessageContext()` throws `"Component is missing a parent <Message /> component."` if called outside the tree `Message.vue` provides via `provideMessageContext`. Any new bubble component must be composed as a child of `Message.vue`, not rendered standalone. Exception by design: `Conversation/ReferralBubble.vue` is *not* a message bubble despite the name — it renders conversation-level referral data standalone from `MessagesView.vue` and never calls `useMessageContext()`.
- **`shouldGroupWithNext` has two layers**: `MessageList.vue` computes a raw `groupWithNext` from sender/type/same-minute grouping, but `Message.vue` derives its own `shouldGroupWithNext` computed that forces `false` when `status === 'failed'` — a grouped bubble that fails to send breaks out of the group visually. Don't conflate the prop with the context value.
- **Reply-to resolution has three fallback tiers** (local `messages` prop -> Vuex `getSelectedChat` -> on-demand `MessageApi.getPreviousMessages` fetch cached in a local `Map`), and the fetch path returns `null` synchronously while the async fetch is in flight ("Let UI handle loading state" per the inline comment) — a bubble reading `inReplyTo` may legitimately see `null` first and get a re-render once the fetch resolves.
- **`isBotOrAgentMessage` has a "no sender at all" special case**: if there's no `sender` and no `senderId`/`senderType`, it's treated as sent by the current user/agent (`return true`) rather than defaulting to false — this affects orientation (right-aligned) for messages with missing sender metadata.
- **Histoire, not Storybook**: component previews use `.story.vue` files and `pnpm story:dev`/`story:build`/`story:preview` (Histoire), configured at repo-root `histoire.config.ts`. When adding a new primitive, the convention in this tree is to ship a co-located `ComponentName.story.vue`.
- **Directory naming is inconsistent by design maturity**: newer/feature folders use PascalCase (`Contacts/`, `Companies/`, `AssignmentPolicy/`, `NewConversation/`), while primitive/design-system folders use lowercase/kebab-case (`button/`, `dropdown-menu/`, `emoji-icon-picker/`). Match the existing convention for the folder you're editing rather than normalizing casing across the tree.
- **Migration is piecemeal, not folder-by-folder**: legacy `dashboard/components/` files (e.g. `ConversationItem.vue`, `MessagesView.vue`) already import individual components from here while the surrounding page/route is still legacy. Don't assume "uses components-next" implies the whole feature has migrated, or that a legacy component is dead code just because a `components-next` equivalent exists elsewhere.
- **Enterprise gating in the frontend is capability-flag based, not a separate override tree**: unlike the Rails `enterprise/` overlay's `prepend_mod_with` pattern, `Sidebar.vue` gates Enterprise-only features (Calls) with a plain `computed` reading `useConfig()`'s `isEnterprise` and `isOnChatwootCloud`. There is no frontend `prepend_mod_with` equivalent observed in this directory.
- **Large "illustration" components**: `captain/AnimatingImg/{Scenarios,Guardrails,ResponseGuidelines,Settings}.vue` are ~750–1060 lines each but are mostly static/animated SVG markup, not complex logic — don't be surprised by their size relative to everything else in the tree; they were not read in full for this page.
- This page samples a 538-file, 234-component tree; large siblings not read in detail include `HelpCenter/`, `Campaigns/`, `Contacts/`, `Companies/`, most of `captain/pageComponents/`, and most standalone primitive folders (`table/`, `combobox/`, `select/`, `selectmenu/`, `taginput/`) — treat file lists above as representative, not exhaustive.
