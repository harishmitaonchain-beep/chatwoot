# Chatwoot AI Wiki

This vault documents the Chatwoot codebase for AI coding agents and humans working in this repo. It covers the Rails/Ruby OSS backend, the Vue 3 dashboard and widget frontend, and the `enterprise/` overlay that extends OSS behavior via `prepend_mod_with`/`include_mod_with`. Each page is scoped to one subsystem or module and is meant to get an agent oriented quickly — architecture, key classes/files, and how the pieces connect — before it starts reading or editing code.

Start at [[00-meta/ai-agent-guide|AI Agent Guide]] for how to use this vault while working a task, or [[00-meta/path-index|the Path Index]] if you already know which file you're about to touch and just want the relevant page fast.

- [[02-backend/macros|Macros]] — Macros::ExecutionService runs an agent-triggered, saved sequence of conversation actions (reply, label, assign, status change, webhook, attachment) sharing the ActionService base with automation rules, extended by an Enterprise required-attributes gate.
- [[02-backend/assignment|Assignment & Round Robin]] — Covers Chatwoot's two parallel conversation auto-assignment systems (legacy synchronous V1 and policy-driven bulk V2) and the shared Redis-backed round-robin queue, rate limiter, and Enterprise capacity/balanced-assignment extensions that sit on top of them.
- [[02-backend/reports|Reports & Analytics Backend]] — Documents Chatwoot's reports/analytics backend: the raw-event write path (ReportingEventListener → ReportingEvent → RollupService/BackfillService into ReportingEventsRollup) and the read path (Reports::DataSource/ReportMetricRegistry, currently raw-only) that powers the V2 reports controller and builders.
- [[02-backend/notifications|Notifications & Mailers]] — Covers the in-app Notification model/services (push via WebPush/FCM/ChatwootHub, email delivery) and the full ActionMailer layer (agent notifications, conversation reply emails, admin/team/portal transactional mail).

- [[02-backend/events-listeners|Event Dispatcher & Listeners]] — A Wisper-based pub/sub layer where a single Dispatcher singleton fans domain events (conversation/message/contact/etc.) out to sync (ActionCable, agent bots) and async (webhooks, automation rules, notifications, reporting, CSAT) listener singletons, extended by Enterprise via prepend_mod_with.
