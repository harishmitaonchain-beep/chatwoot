## Method

1. **Module map.** The repo's actual directory structure (`app/`, `enterprise/app/`, `app/javascript/`, `config/`) was scouted first to build a list of ~35 modules — each one a real, existing set of paths, not a guessed taxonomy.
2. **External grounding, fetched once.** Two outside sources were pulled and condensed into shared context handed to every agent:
   - [deepwiki.com/chatwoot/chatwoot](https://deepwiki.com/chatwoot/chatwoot) — a third-party AI-generated wiki's table of contents, used only as a structural checklist (its content was never fetched or copied).
   - [chatwoot.help/hc/user-guide](https://chatwoot.help/hc/user-guide/en) — the official product user guide's category/article list, used to ground "Product Behavior" sections in real product features rather than invented UI copy.
3. **One agent per module**, running in parallel, each: read the module's actual code (Glob/Grep/Read, sampling intelligently on large directories rather than reading every file), then wrote one Markdown page with YAML frontmatter, cross-linked to sibling pages via `[[wikilinks]]`.
4. **Synthesis pass**: a root `README.md` map-of-content, an [[ai-agent-guide|AI agent usage guide]], and a [[deepwiki-crosscheck|DeepWiki cross-check]] that honestly flags what this vault does *not* yet cover (see its "Suggested follow-up pages" list).
