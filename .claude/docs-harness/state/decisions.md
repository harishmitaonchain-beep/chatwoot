# Decisions: method, naming, rules

## Two kinds of docs

### 1. Feature and channel journeys (four stages)

| Stage | Reader asks | Must include |
|---|---|---|
| 1 Discover | Can I do this, and can I use it? | One-line verdict. Plan & access (plan, role, beta, inbox type). Link to Pricing & Plans. How to check you have it. |
| 2 Set up & try | How do I get it working? | Prerequisites before step 1. Steps in the product's exact UI labels. A Test it step. |
| 3 Get value | Am I using it well, and what are the limits? | Good practice. What to expect. Where to see results. |
| 4 Troubleshoot | Why is it not working? | Symptom, likely cause, what to do. Silent failures called out. When to contact support and what to send. |

### 2. Supporting layers (not journeys)

Onboarding and education, account setup, migration, shared building blocks,
reference, quick how-tos, and one central Pricing & Plans page.

## Rules that hold everywhere

- The public pricing page wins over the code on plans. Plan names: Hacker
  (free), Startups, Business, Enterprise. Never write "free plan" alone.
- Never describe usage as a hard limit. Chatwoot does not enforce hard limits.
  A provider's own limit (Meta's messaging limit) can be explained.
- Shared topics live once and are linked, never repeated.
- No em dashes. Use commas, colons, periods, or parentheses.
- Unverifiable claims become "⚠️ Confirm:", never guesses.
- Public sources only.
- When a feature's variants differ in audience, gating, or setup, give each its
  own journey and link them from a hub. Channel journeys own their
  channel-specific feature pages (the WhatsApp journey owns WhatsApp campaigns).

## Conventions in drafts

- `[Link: X]` is a link to a page that does not exist yet.
- `📸 Add screenshots (self note):` marks where screenshots go, with exact screens.
- `⚠️ Confirm:` marks an open question.
- Every page ends with Review notes, removed before publishing.
